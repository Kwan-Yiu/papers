# Notes

Keep each close-reading note to roughly one page:

```markdown
# Paper

## Problem and workload

## Bottleneck evidence

## Cost model

## Mechanism

## What semantics/quality is preserved

## Strongest baseline

## Main result

## Where it stops working

## Code path to inspect

## One experiment to reproduce

## One open question
```

Do not restate the abstract. The value of a note is placing the paper in a unified
`compute / memory / overhead / communication / queueing / quality` framework.
